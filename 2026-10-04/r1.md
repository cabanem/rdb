# R-1 Issue invitations to the Workflow App (POST) — rebuilt step list

Keeps the shape of the current recipe (try/catch, OBS-01 events, per-request INV-01 call, concurrency 1). Changes: honours `exclude_supplier_request_ids`; empty pending set is a 200 not a 500; 409 for state problems; failed INV-01 calls stay in the results; the self-referencing `secondary_dispositions` pill is repointed; the summary uses the buckets the library renders; `results` carry names and a message, not only IDs.

INV-01 contract this is written against: `transitioned` (bool), `assignee_disposition` ∈ `sent | failed | already_invited`, `secondary_dispositions[] { disposition, secondary_user_email }`.

## Trigger — API Platform · New API request (endpoint `POST invitations`, Provisioning (GAS))

Request (JSON body):

| field | type | optional |
|---|---|---|
| `batch_id` | string | no |
| `analyst_email` | string | no |
| `spreadsheet_id` | string | no |
| `exclude_supplier_request_ids` | array of string | **yes** (new) |
| `timestamp` | string | yes |
| `payload_version` | string | yes |

Responses:
- `200` — `ok` (bool), `batch_id`, `started_at`, `completed_at`, `summary { total, invited, partial, already_invited, assignee_failed, skipped_excluded, skipped_no_primary, skipped_state, system_errored }` (all integers), `results[] { supplier_request_id, supplier_name, assignee, status, message, transitioned, assignee_disposition, secondary_dispositions }`.
- `400`, `409`, `500` — `error_details { code, error_message, errored_action }`.

The library's modal reads `supplier_name`, `status`, `assignee`, `message` from each result; its one-line summary reads the bucket names above (`skipped_excluded` is new — see note at the end).

### Code block A — step 12 "Select candidates"

```python
def main(input):
    records = input.get("records") or []
    exclude = {str(x).strip() for x in (input.get("exclude_ids") or []) if str(x).strip()}

    def shape(r):
        return {
            "supplier_request_id": str(r.get("supplier_request_id") or "").strip(),
            "supplier_name":       str(r.get("supplier_name") or "").strip(),
            "assignee_email":      str(r.get("assignee_email") or "").strip(),
        }

    candidates, excluded = [], []
    for r in records:
        s = shape(r)
        if not s["supplier_request_id"]:
            continue
        (excluded if s["supplier_request_id"] in exclude else candidates).append(s)

    return {
        "candidates": candidates,
        "excluded": excluded,
        "candidate_count": len(candidates),
        "excluded_count": len(excluded),
    }
```

Output schema sample: `{"candidates":[{"supplier_request_id":"…","supplier_name":"…","assignee_email":"…"}],"excluded":[],"candidate_count":1,"excluded_count":0}`.

### Code block B — step 20 "Batch summary"

```python
# Buckets are the keys Invitations._formatSummary (lib_sdc) renders. One row lands in exactly one bucket.
#   invited          transitioned, assignee sent, every secondary sent (or none)
#   partial          transitioned, assignee sent, at least one secondary not sent
#   already_invited  assignee_disposition already_invited
#   assignee_failed  assignee_disposition failed
#   system_errored   INV-01 threw (error set) or an unrecognised disposition
#   skipped_excluded left out by the request's exclude list (never called INV-01)
#   skipped_no_primary / skipped_state  reserved; INV-01 does not emit them today, so they stay 0

def to_bool(v):
    return v is True or str(v).strip().lower() in ("true", "1", "yes")


def main(input):
    rows = input.get("results") or []
    excluded = input.get("excluded") or []
    summary = {k: 0 for k in ("total", "invited", "partial", "already_invited", "assignee_failed",
                              "skipped_excluded", "skipped_no_primary", "skipped_state", "system_errored")}
    out = []

    for r in rows:
        disp = str(r.get("assignee_disposition") or "").strip().lower()
        err = str(r.get("error") or "").strip()
        secs = r.get("secondary_dispositions") or []
        sec_failed = [s.get("secondary_user_email") or "?" for s in secs
                      if str(s.get("disposition") or "").strip().lower() != "sent"]
        transitioned = to_bool(r.get("transitioned"))

        if err:
            bucket, message = "system_errored", err
        elif disp == "already_invited":
            bucket, message = "already_invited", "Primary contact was already invited."
        elif disp == "failed":
            bucket, message = "assignee_failed", "Invitation to the primary contact failed."
        elif disp == "sent" and transitioned:
            if sec_failed:
                bucket = "partial"
                message = "Primary invited; secondary contact(s) not sent: " + ", ".join(sec_failed)
            else:
                bucket = "invited"
                message = "Invited" + (" (+%d secondary)" % len(secs) if secs else "") + "."
        else:
            bucket = "system_errored"
            message = "Unrecognised outcome (transitioned=%s, disposition=%r)." % (transitioned, disp)

        summary[bucket] += 1
        summary["total"] += 1
        out.append({
            "supplier_request_id": r.get("supplier_request_id") or "",
            "supplier_name":       r.get("supplier_name") or "",
            "assignee":            r.get("assignee_email") or "",
            "status":              bucket,
            "message":             message,
            "transitioned":        transitioned,
            "assignee_disposition": disp,
            "secondary_dispositions": secs,
        })

    for e in excluded:
        summary["skipped_excluded"] += 1
        summary["total"] += 1
        out.append({
            "supplier_request_id": e.get("supplier_request_id") or "",
            "supplier_name":       e.get("supplier_name") or "",
            "assignee":            e.get("assignee_email") or "",
            "status":              "skipped_excluded",
            "message":             "Excluded by the request.",
            "transitioned":        False,
            "assignee_disposition": "",
            "secondary_dispositions": [],
        })

    return {"summary": summary, "results": out}
```

Output schema sample: `{"summary":{"total":2,"invited":1,"partial":0,"already_invited":0,"assignee_failed":0,"skipped_excluded":1,"skipped_no_primary":0,"skipped_state":0,"system_errored":0},"results":[{"supplier_request_id":"…","supplier_name":"Acme","assignee":"a@b.c","status":"invited","message":"Invited.","transitioned":true,"assignee_disposition":"sent","secondary_dispositions":[]}]}`.

## Notes

- **`skipped_excluded` is a new bucket.** Add one line to `Invitations._formatSummary` in lib_sdc so it shows: `if (summary.skipped_excluded) parts.push(summary.skipped_excluded + ' excluded');`. Without it the count is still in `data.summary`, just not in the one-liner.
- Step 9's mismatch guard is the only place `spreadsheet_id` is used. Under the router it should never fire; if it does, the registry row is wrong, not the workbook.
- The 1000-row limit on step 11 is a ceiling, not a page. Rosters above that need pagination or the async shape; see the timing note in the previous reply before investing here.
- `transitioned`, `assignee_disposition` and `secondary_dispositions` are kept on each result for the OBS record and for anyone debugging; the modal ignores them.
